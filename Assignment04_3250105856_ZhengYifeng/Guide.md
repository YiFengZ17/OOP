# A4 Personal Diary：动手指南

目标：自己完成四个独立程序，共用一套日记代码，再用一个脚本完成分发和测试。本文是一条推荐路线，不是唯一设计；先完成每一步的小验证，再继续。

## 一、先想清楚怎么工作

```text
命令行参数 → 检查参数、解析日期
                     ↓
              从同一个文件加载日记
                     ↓
              添加 / 列出 / 查看 / 删除
                     ↓
                保存文件、返回状态
```

四个程序分别编译成 `pdadd`、`pdlist`、`pdshow`、`pdremove`。它们共享源代码和数据文件，不在程序内部互相调用。

| 命令 | 行为 |
| --- | --- |
| `pdadd 日期` | 逐行读取内容，单独一行 `.` 或文件结束（EOF）时停止；同日期覆盖 |
| `pdlist` | 按日期顺序列出所有条目 |
| `pdlist 起始日期 结束日期` | 列出范围内条目，本方案包含两个端点 |
| `pdshow 日期` | 只输出该日内容，便于重定向 |
| `pdremove 日期` | 删除条目；成功返回 `0`，所有失败返回 `-1` |

日期统一用 `YYYYMMDD`。本方案允许空日记；`pdlist` 每篇输出一行“日期 + 制表符 + 首行摘要”。这些是设计约定，写进最终 README 即可。

## 二、代码怎么分

保留三个小类型，不设 `cli.h / cli.cpp`：

| 类型 | 数据与职责 |
| --- | --- |
| `Date` | 保存日期；校验、比较、转成字符串 |
| `Entry` | 一篇日记：日期和 `vector<string>` 内容；用简单 `struct` 即可 |
| `Diary` | 用 `map<Date, Entry>` 管理全部条目；负责文件读写、增删查询 |

`map` 自动按日期排序、保证键唯一；**覆盖旧条目仍要由你的代码实现**。`Entry` 只放数据，暂时不需要单独的 `.cpp`。

```text
code/
├── Date.h       Date.cpp
├── Entry.h
├── Diary.h      Diary.cpp
├── pdadd.cpp    pdlist.cpp    pdshow.cpp    pdremove.cpp
├── pd.sh
└── Makefile                     # 最后再写也可以
```

每个 `main` 自己检查参数并调用 `Date::parse`。允许重复这几行简单流程，不重复实现日期校验和文件读写。

## 三、按五步实现

### 第 1 步：日期与条目

**思路：** 先保证日期可靠，再让它成为日记的索引。

**你来写：**

- `Date::parse(text, out)`：检查八位数字、月份、每月天数和闰年；成功才修改 `out`，用 `bool` 表示成功与否。约定年份为 `0001`～`9999`。
- `Date::toString()`：输出补零后的八位日期。
- `Date::operator<`：按年、月、日比较，供 `map` 排序。
- `Entry`：只包含 `Date date` 和 `vector<string> lines`。

若用默认构造的 `Date` 接收解析结果，必须检查解析成功后才能使用它。

**完成标志：** `20240229` 合法，`20230229`、`20261301`、`abc` 非法；日期能正确比较先后。

### 第 2 步：先实现内存中的日记

**思路：** 暂时不碰文件，先把增删查跑通。

`Diary` 内部保存私有的 `map<Date, Entry>`，提供这些操作：

| 操作 | 建议接口行为 |
| --- | --- |
| `add(entry)` | 同日期存在就替换，否则插入 |
| `remove(date)` | 删除成功返回 `true`，不存在返回 `false` |
| `find(date, out)` | 找到则把条目复制给 `out` 并返回 `true` |
| `all()` | 按日期返回 `vector<Entry>` |
| `between(start, end)` | 返回闭区间内的 `vector<Entry>` |

这里返回副本，避免先引入指针生命周期（lifetime）问题；小作业的数据量下足够使用。范围查询先遍历筛选即可，不必急着优化。

**完成标志：** 乱序添加三篇后有序列出；同日添加不会增加篇数；删除不存在的日期返回失败。

### 第 3 步：加上加载与保存

**思路：** 文件只是内存数据的保存形式。统一由 `Diary` 读写，四个 `main` 不各写一套。

本方案使用文本格式：

```text
20261105
Learned C++.
Second line.
.
20261106
Another entry.
.
```

日期行之后都是内容，直到单独一行 `.`。通过 `pdadd` 输入的正文不会包含这种行，因此可用它分隔条目。

**你来写：**

- `load(path)`：逐篇解析，放进内存；只有文件确实不存在才视为空日记，其他打开或读取错误应返回失败。
- 数据文件中日期非法、条目缺少结束行 `.`，都按损坏处理，停止操作，不保存残缺数据。
- `save(path)`：写出全部条目；检查写入及关闭是否成功。
- 默认路径为当前工作目录下的 `diary.dat`；允许环境变量（environment variable）`PD_DATA` 指定其他路径，方便隔离测试数据。

**保存策略：** 按题目字面要求，四个程序正常完成操作后都写回。先写同目录临时文件，成功关闭后再替换原文件；Linux 下可使用 `std::rename` 并检查返回值。每次保存使用独立临时文件名，失败时保留原文件。

这样避免直接截断原文件，也能支持本作业的 `pdshow A | pdadd B` 演示。它不保证多个修改命令同时运行时不会覆盖彼此；本作业先按顺序执行修改命令。

**完成标志：** 保存后重新加载，日期、空行及正文仍一致；损坏文件会报错，原文件不会被覆盖。

### 第 4 步：接上四个 main

**思路：** 每个入口只做参数处理、调用公共代码、输入输出和返回状态。

共同顺序：检查参数 → 解析日期 → 加载 → 执行操作 → 保存 → 返回状态。任一步失败都应停止，不继续保存。

| 程序 | 你需要补的逻辑 |
| --- | --- |
| `pdadd` | `argc == 2`；用 `getline` 读内容，遇到 `.` 或正常 EOF 停止；读取错误要报错；构造条目并添加 |
| `pdlist` | `argc == 1` 或 `3`；有范围时检查起始不晚于结束；遍历结果输出 |
| `pdshow` | `argc == 2`；查找条目，找到后逐行输出正文；不存在则失败 |
| `pdremove` | `argc == 2`；删除不存在的日期也算失败；失败统一 `return -1` |

标准输出（stdout，`cout`）只放结果；错误和使用说明写到标准错误（stderr，`cerr`）。其余三个程序成功返回 `0`，失败返回 `1`。

输入文件可能使用 Windows 换行，读行后可去掉末尾的 `\r`。正文按行保存，输出时补换行，不要求保留原输入末尾是否有换行。

先用以下命令编译，之后再整理成 Makefile：

```bash
for p in pdadd pdlist pdshow pdremove; do
    g++ -std=c++17 -Wall -Wextra "$p.cpp" Date.cpp Diary.cpp -o "$p" || break
done
```

**完成标志：** 手动跑通四个命令，并验证 `pdadd 日期 < note.txt`、`pdshow 日期 > output.txt`。Unix 下 `return -1` 在 shell 中显示为 `255`，这是正常的。

### 第 5 步：一个 pd.sh，两种模式

**思路：** 脚本只负责调用程序，不重新实现日记功能。

```bash
bash pd.sh pdadd 20261105    # 分发模式：转交给指定程序
bash pd.sh pdlist
bash pd.sh test             # 测试模式：依次运行全部案例
```

**你来写：** 用 `case` 判断第一个参数：

- `pdadd / pdlist / pdshow / pdremove`：用 `shift` 去掉程序名，把剩余的 `"$@"` 交给对应程序；程序路径相对脚本目录确定。
- `test`：用 `mktemp -d` 创建临时目录，把 `PD_DATA` 设置为其中的数据文件；依次运行下面的案例，结束后清理临时目录。
- 其他情况：输出用法并返回失败。

测试模式至少覆盖：

1. 添加两篇日记，分别使用 `.` 和 EOF 结束输入。
2. 覆盖同一天，检查旧内容消失。
3. 列出全部日记和日期范围，检查顺序及端点。
4. 查看内容，使用 `pdshow A | pdadd B` 复制并检查其他条目仍在。
5. 删除成功后再删一次，检查退出状态分别为 `0`、`255`。
6. 非法日期、参数不足、范围颠倒，均应失败。

每个案例标出预期结果并检查实际结果；不要只运行命令就宣布通过。可用 shell 条件判断退出状态、用 `diff` 比较输出文件，不需要测试框架。
